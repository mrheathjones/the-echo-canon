# tools/ — drift-prevention tooling

Two scripts that keep the canon from drifting out of sync with itself.

## `validate.sh` — continuity gate
Runs cheap, high-signal checks against `canon/` and exits non-zero on a real break.

- **FAIL** (blocks a push): missing required canon file; no Book 1 spine; the retired
  surname collision `Maya Whitmore`; a broken cross-link inside `canon/`.
- **WARN** (advisory, never blocks): a `Jonesepies` placeholder still present; a first
  name used in the registry across sections as two different people (e.g. the two
  Sarahs); a `MASTER_CANON_BIBLE.md` that isn't a generated rollup.

```bash
bash tools/validate.sh        # exit 0 = OK to push, 1 = fix FAILs first
```
`source/` is raw archival material and is deliberately never validated.

**Wire it into every push.** Any update script should run this before `git push`:
```bash
bash tools/validate.sh || { echo "validation failed — not pushing"; exit 1; }
```

## `build_bible.sh` — regenerate the master bible
`MASTER_CANON_BIBLE.md` is a **derived** artifact. This rolls up *every* file under
`canon/` into one document (ordered where known, appended where not), with a
"do not edit" banner. Because it always includes every canon file, the bible can't
silently fall behind canon.

```bash
bash tools/build_bible.sh     # rewrites MASTER_CANON_BIBLE.md; review diff, then commit
```
Do not hand-edit `MASTER_CANON_BIBLE.md` — edit the files under `canon/` and re-run.
(The `.docx`/`.pdf` copies are not regenerated by this script.)

## The drift-prevention loop
1. Edit truth in `canon/` only.
2. `bash tools/validate.sh` — fix any FAILs.
3. `bash tools/build_bible.sh` — refresh the rollup.
4. Commit; push only when validate passes.
