# The Echo — Journal Template
_Use this when running "wrap up." The journal lives at `notes/THE_ECHO_CONTEXT_JOURNAL.md`._

The journal is a dated SNAPSHOT for the next session to rehydrate from — **not** canon. The
repo's `canon/` files win on any conflict. State that at the top. Keep it scannable; refresh the
dynamic sections (4–10) each session; don't bloat it.

## Required structure
```
0. How to use / source-of-truth note + pointer to the full transcript (if any)
1. Project in one paragraph
2. Locked decisions (condensed)
3. Endgame + second clock
4. Latest review triage (accepted / nuanced / pushed back)
5. Scenes — status (drafted · needs-revision · NEXT)
6. Repo facts (URL, branch, journal path, tools)
7. Bible status / plan
8. Workflow rules (one-shot pattern, validate, credentials, local clone path)
9. File / path locations
10. Open items + **THE SINGLE NEXT MOVE**   ← the next session starts here
```

## On "wrap up", update at minimum:
- **§5 Scenes** — move anything drafted this session to its new status; name what's next.
- **§4 Review triage** — if a review came in, record accepted vs nuanced points.
- **§10 Open items / next move** — the most important line in the file. Make the next move
  concrete enough that a fresh session can act on it immediately.
- **Date** the file (top of §0).
- If canon changed, note *that* it changed and point to the file — but keep the canon detail in
  the repo, not in the journal.

## Keep it honest
Anything in the journal that has become real, locked canon belongs in `canon/` too (and in
`canon/CHANGELOG.md`). The journal records narrative state and the next move; the repo records truth.
